# Histórico local de execuções

O histórico da comparação demonstrativa é salvo no `localStorage` do navegador, sob a chave `agroville-run-history-v1`. Ele não usa servidor, banco remoto ou autenticação. A interface limita o histórico a 20 registros e a 2 MiB do valor JSON serializado. O tamanho é medido em bytes UTF-8 da string exata persistida; não inclui o nome da chave nem outros dados de `localStorage`. Os 2 MiB são uma política do produto, não uma previsão da cota do navegador, que depende da implementação e do uso de outras chaves. A tela informa a contagem e o uso atuais.

Cada item tem `id` UUID, timestamp ISO 8601, operação (`comparison`), status (`completed` ou `failed`), fator e duração do cenário, seed, versão de compatibilidade do motor, resultado quando concluído e proveniência local. A entrada `manifest` reutiliza o manifesto de comparação já existente e guarda o snapshot inicial usado para reproduzir a execução. Snapshot e eventos são reduzidos aos campos necessários pelo motor; campos extras vindos de um manifesto importado não são copiados. Nenhum token, credencial, caminho local ou stack trace é registrado.

O módulo [`run-history.js`](../src/client/run-history.js) expõe `createRunRecord`, `recordRun`, `listRuns`, `getRun`, `runCompatibility`, `getRunHistoryStats`, `exportRunHistory` e `clearRunHistory`. Os registros são priorizados por timestamp mais recente e, em empate, por ID em ordem determinística. Ao salvar, o módulo percorre essa ordem e mantém até 20 registros cujo envelope serializado caiba em 2 MiB. Um registro que não cabe é pulado para permitir que registros menores mais antigos sejam mantidos. Se a execução nova, sozinha, exceder o limite ou não couber entre os registros prioritários, ela não é gravada e o histórico anterior fica intacto. A interface informa quando registros antigos foram removidos pelos limites; exporte uma cópia antes de novas execuções para manter esses registros.

**Exportar histórico** baixa o valor atual da chave como JSON sem alterá-la. Se o conteúdo estiver corrompido, o arquivo preserva o texto bruto para recuperação. **Limpar histórico** exige confirmação e remove somente essa chave. A exportação permanece disponível antes da limpeza.

O botão **Reproduzir** usa o manifesto original salvo e o validador/replayer existente em [`engine.js`](../src/client/engine.js). Versões de motor ou manifesto incompatíveis são identificadas e não executadas. O histórico não cria outro formato de snapshot ou replay, nem substitui os arquivos exportáveis de manifesto.

Ausência de dados inicia um histórico vazio. JSON truncado, estrutura desconhecida e armazenamento inacessível geram erro visível e não são sobrescritos por uma nova gravação; a exportação ainda pode baixar o texto bruto quando a leitura da chave funciona. Cada tentativa de gravação faz uma única chamada `setItem` com o envelope retido. Não há remoção preventiva, repetição após erro de quota ou limpeza automática de outras chaves. Se `setItem` falhar, esta implementação preserva o valor anteriormente armazenado, a comparação continua visível e a interface informa que ela não foi salva. A especificação Web Storage determina que `setItem` lance `QuotaExceededError` quando não pode definir o valor. A leitura, seleção e gravação não formam uma transação entre abas: alterações concorrentes no mesmo navegador podem se sobrescrever, pois Web Storage não oferece bloqueio entre contextos.

Esta versão registra o fluxo de comparação do motor principal. A simulação científica BR-CORTE tem contrato próprio e não é incluída neste MVP.
