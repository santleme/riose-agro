# RIOSE

**An exploratory, deterministic livestock simulation with an experimental AMD ROCm metabolism path.** RIOSE lets users configure and compare modeled cattle-farm scenarios; its outputs are illustrative, not farm predictions or management advice.

[Live demo](https://agro-smallville-mvp.qwdqwdwqdqdqwdwwqqw.chatgpt.site/product.html) · **Demo video:** COMING SOON · [AMD validation evidence](docs/evidence/amd/AMD_VALIDATION.md)

![RIOSE Product scenario](docs/act-iii/screenshots/product-scenario.png)

## Problem

Feed, housing, and pasture choices interact. RIOSE makes scenario assumptions and the resulting modeled differences visible for exploration.

## Solution

The Product browser experience runs deterministic scenarios and compares two 30-day cases from the same illustrative farm snapshot and seed. The example comparison changes housing (pasture versus confinement) while holding diet, supplement, and weather fixed.

## How it works

1. Configure a cattle-farm scenario in Product.
2. Run the deterministic engine in a browser Worker.
3. Inspect modeled outcomes and compare scenarios with their assumptions visible.

## Technical architecture

The AMD service handles one metabolism batch inside the larger simulation. Other simulation rules and the browser experience remain in the deterministic Product engine.

```text
Browser Product UI
  → scenario management
  → FarmEngine / Worker
      ├─ default: JavaScript CPU metabolism
      └─ AMD selected: metabolism batch
          → Product server proxy (/api/amd/metabolism-batch)
          → Python compute service (/api/compute/v1)
          → PyTorch CPU or AMD ROCm
          → AMD Instinct hardware (only on a compatible host)
```

When AMD is selected, Product applies a step only after the service confirms ROCm execution; unavailable hardware or fallback is reported instead of being labeled as AMD.

## Scientific foundation

The full engine is illustrative and has not been calibrated against a target farm or validated to predict real outcomes. Observed study measurements are shown separately from simulated outputs. Component diagnostics do not validate the full model or establish causal effects.

See [parameter assumptions and sources](docs/parametros-e-fontes.md), [scientific model scope](docs/modelos/br-corte-2023-cms-pasto.md), [scientific model architecture](docs/architecture/scientific-models.md), and the [uncertainty policy](docs/politica-incerteza.md).

## Evidence status

- **OBSERVED** — measurements from cited datasets; kept separate from model output.
- **SIMULATED** — results generated by the current deterministic rules.
- **ASSUMED** — scenario inputs and model parameters without farm calibration.
- **EXPERIMENTAL** — the opt-in AMD/ROCm metabolism integration.
- **VALIDATED** — only the specific check, workload, hardware, and commit stated in its evidence.
- **FUTURE** — planned work that is not implemented or verified.

## Validation

The AMD evidence records exact parity for the 24-animal metabolism batch on the stated MI300X VF. It does not establish whole-farm biological validity, full-simulator AMD execution, or a performance improvement. Historical CPU, CUDA, benchmark, and component-diagnostic results are separate evidence and are not substituted for this run.

For software checks, run `npm test` and `npm run test:scenarios`. To repeat the AMD verifier, use compatible AMD hardware and the instructions below; a CPU-only host cannot produce the hardware result above.

## Run locally

Requires Node.js 20 or newer. From the repository root:

```sh
npm ci
npm start
```

Open `http://127.0.0.1:8000/product.html`. The local server binds to loopback by default.

## AMD compute instructions

On a host with a supported PyTorch ROCm runtime, start the services in separate terminals:

```sh
python3 src/server/compute_service.py
npm start
```

Open Product, select **AMD · ROCm**, and advance the simulation. To verify the metabolism batch against the JavaScript reference, keep the compute service running and run:

```sh
npm run verify:amd-livestock
```

The verifier fails if the requested AMD backend does not execute or parity exceeds the configured absolute and relative tolerance (`1e-12`). It does not silently turn a CPU run into AMD evidence.

- `scripts/verify-amd-livestock.mjs`, `tests/` — AMD batch verifier and software checks.
- `docs/evidence/amd/` — the hardware-validation record and supplied screenshots.
- `docs/modelos/`, `docs/parametros-e-fontes.md`, `docs/politica-incerteza.md` — model scope, sources, and limits.

## Current limitations

RIOSE is a software prototype, not a calibrated farm model. Its outputs are not validated farm predictions, causal management recommendations, or animal-management advice. The AMD result is a hardware check of one metabolism batch, not validation of all simulation logic. The live demo is an existing Agroville-hosted Product route; a dedicated demo video is not available.
