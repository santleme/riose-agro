# Testing strategy

Preserve the current 497-test suite as the baseline recorded by P3-011; remeasure the actual checkout before changes. For P4 sensitivity test public request/response seams: schema, valid worked values, exact intervals, boundaries, bad units/shapes, invalid increments, point cap, fixed-input invariants, results/provenance and deterministic replay. Use independently sourced Eq. 2.6 reference fixture, not a second copy of implementation arithmetic.

For UI use local Playwright E2E: blank initial state, explicit example, review values, no auto-run, confirmation, actual result table/curve, keyboard/reduced-motion/mobile and export/replay. Run Product V2/V3 E2E and full `npm test`; run JS/Rust parity only when shared engine code changes. Browser benchmarks only for measurable performance changes and compare before/after with same harness/configuration. Tests establish software behavior, not model validity.


For the hybrid continuation, the actual baseline was 510 Node tests, now 522. `test:e2e:scenario-lab` explicitly exercises deterministic interpretation, independent of server credentials; the old AI fixture and new decision-contract E2E label themselves as fixtures. Live E2E scripts require `RIOSE_LIVE_AI=1` and an actual server provider; they assert `source=llm`, save sanitized metadata and never substitute a fixture for a live failure. Real tests are manually authorized and bounded by account limits; default npm tests make no remote inference calls.

The new public contract tests cover request/response byte limits, incomplete JSON output, safe authentication/quota/timeouts, numeric source/roles, domain exclusion, missing units/weather/price basis, currency, follow-up edits, schema injection, grounded results and versioned single-report evidence/implementation hashes. Browser checks cover stale-response rejection, explicit engine execution, provider-outage/invalid-import output retention, offline assumptions, typed sensitivity summaries, keyboard focus, reduced motion and mobile scientific-provenance wrapping.

Laya evaluation uses a frozen 32-case bilingual fixture, a fixed model/question, and independently reported development/final metrics. Labels/thresholds are not tuned using final results. The new lexical comparator is explicitly disclosed as non-blinded; all outcomes are exploratory smoke evidence. A negative promotion screen is a valid completed evaluation. New candidates need a separate protocol and fresh held-out user evidence. Reproduction commands and raw artifact scope are documented in the local runtime guide and live validation report.
